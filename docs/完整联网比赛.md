# 独立服务器完整联网比赛

本项目基于 Lyra 框架，将自研英雄 GAS 技能、轮换控制点与战术 HUD，与宿主提供的移动、武器网络同步、ShooterCore 计分判定及切图流程协同运行。在独立专用服务器与拥有客户端的同机环境中，完成占点争夺、阵亡重生、自然结算并加载新世界，记录业务扩展与宿主比赛生命周期的衔接。

[完整实机视频与项目详情](https://ubik42.github.io/?work=lyra-hero-arena)

## 本次结果

- UE 5.7.4，非打包 Development，同机 Loopback，独立 Dedicated Server 与一个拥有客户端，配置九个 Bot。
- 每端各设置 80 ms 出站延迟、1% 出站丢包。该设置不等于精确 RTT，不代表公网或多客户端并发结果。
- 从 0:0 正常推进到 **150:121**，队伍 1 达到目标分，原生 PostGame 结束计分；采样到的赛后同世界时段约 9.32 秒，比分保持不变。
- 双端进入新的世界，比分重置为 0:0，服务器再次进入 Playing。客户端清除赛后提示，显示新的活动目标。
- 本次玩家属于队伍 2，结算界面显示失败。视频上方按固定队伍 1 / 队伍 2 标注；游戏 HUD 按本方 / 敌方显示，左右顺序可能不同。

连续画面约 **8 分 12 秒**，共 6632 帧。按实际经过时间编排，无声。最长约 2.21 秒没有新采集帧，保留为上一帧停留，不压缩时间。采集影响运行开销，这段视频不用于性能测量。

## 输入与采集

验证流程由非 Shipping 构建下显式启用的本地探针驱动。读取服务器只读导航与视线目标，结合客户端视角，经 Enhanced Input 输入移动、开火和技能。自动输入属于录制辅助，不是客户端 AI 或新增玩法。没有开启无敌、传送、注入伤害、强制占点或调用强制结算。

新增代码入口：

- [HeroArenaNetworkProbe.cpp](../Plugins/GameFeatures/HeroArena/Source/HeroArenaRuntime/Private/HeroArenaNetworkProbe.cpp)：本地文件队列、允许列表、单次和持续输入、采集启动停止。
- [HeroArenaProcessCapture.cpp](../Plugins/GameFeatures/HeroArena/Source/HeroArenaRuntime/Private/HeroArenaProcessCapture.cpp)：原生 FFrameGrabber 采集、实际时间戳、JPEG 输出。
- [脱敏双端记录](data/network-full-match.json)：比分、阶段、世界切换和只读玩法采样。原始机器日志及失败录像留在本地。

运行仍需要合法 Lyra 宿主与项目资产，见 [接入与验证](接入与验证.md)。沿用 [跨进程入口](跨进程网络案例.md)，服务器地图参数改为 `?NumBots=9`，完整比赛不执行其中的 Place、阻断、Eliminate 或 FinishRound 定向测试命令。

客户端可发送 `CaptureStart` / `CaptureStop`，帧保存到 `Saved/PortfolioNetwork/<run>-client/frames`。`Input <action-path> <x> <y>` 注入一次，`Hold <action-path> <x> <y>` 持续注入；仅接受源码列出的移动、视角、武器与 Striker 技能路径。动作结果仍由原游戏输入、GAS 与网络逻辑处理。

本记录覆盖一次自然完整联网比赛及下一局启动。公网、断线重连、多客户端并发与长时间运行仍需各自验证。
