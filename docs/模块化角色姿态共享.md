# 模块化角色：独立动画与 Leader Pose

UE 5.7.4 原生 PIE。原创机器人由头、上身、下身三个骨骼网格组成，采用同一套 15 骨骼层级和两秒循环动作。Blender 源文件、FBX、导入脚本和 UE 资产放在 `Samples/ModularPoseLab`。

## 同一角色的两种更新方式

| 模式 | 动画实例 | 可见网格组件 | LOD0 材质分段 |
| --- | --- | --- | --- |
| 独立更新 | 3 | 3 | 7 |
| Leader Pose | 1 | 3 | 7 |

独立模式由三个组件分别播放同一个 AnimSequence。共享模式由隐藏的完整骨架计算姿态，三个可见部件通过 `SetLeaderPoseComponent` 读取骨骼变换；部件自身不创建动画实例。隐藏驱动组件设为 `AlwaysTickPoseAndRefreshBones`，保留完整带权重骨架，保证不可见时仍更新部件需要的骨骼。切换时读取现有播放位置，让新的驱动沿用动画时间。

运行记录包含组件状态、动画实例数量、可见部件数量，以及头、左前臂、左脚的世界坐标。共享模式下，这些采样点与驱动骨架的位置差为 0 cm。该检查覆盖本次同骨架资产；异构骨架、额外布料骨骼和独立物理需要另外设计。

共享姿态减少本例的动画实例，三个部件仍分别渲染。表内的分段数读取 LOD0 资产数据，实际 Draw Call 还受到 Pass、阴影等因素影响。本例没有进行 CPU/GPU 耗时测量。

## 运行

1. 在 UE 5.7 工程启用本仓库 `PerformanceLab` 插件。将样例的 `Content/ModularPoseLab` 复制到工程同名目录；使用有本地 PlayerController 的关卡进入 PIE。
2. 执行 `PerformanceLab.Debug.Modular independent`。命令创建临时机器人、地台和相机。
3. 执行 `PerformanceLab.Debug.Modular leader` 切换共享姿态；`snapshot` 将当前状态写入日志。
4. 执行 `PerformanceLab.Debug.Modular off` 清理临时对象、恢复视角。命令仅编译到非 Shipping 版本。

机器人放在世界坐标 (6000, 6000, 2200)，复用关卡照明；其他关卡应为该区域提供照明并避免遮挡。当前组件关闭碰撞，动作是原地循环，用来观察姿态共享。

## 从源文件重建

优先使用随附 UE 资产。需重建时，将样例 `ContentSource` 和 `Scripts` 放到宿主工程根目录：Blender 后台运行 `make_modular_robot.py`，再依次在 UE Python 中运行 `import_modular_robot.py` 与 `finish_modular_assets.py`。UE 命令行路径使用正斜线。导入脚本默认保护已有资产，重新导入需要显式 `-ModularPoseReimport`。
