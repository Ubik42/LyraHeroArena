# 闪现充能倒计时：隔离客户端时钟偏差

Phase 每 4 秒恢复一格充能，上限 3 格。旧界面用服务器截止时间减去 GameState 在客户端估计的服务器时间，历史启动记录曾显示 7.54 秒。本次在仅向拥有者复制的充能结构中加入快照时间与周期编号：先在**同一服务器时钟基准**上计算剩余时长，再用客户端本地游戏时间递减。服务器继续负责充能恢复与技能激活判定。

同一周期的后续状态只缩短显示，避免再次扣减或请求确认重启倒计时；新周期重新计时，ResetEpoch 隔离换人和重生。独立服务器测试中，两端各配置 150 ms 出站延迟与 2% 出站丢包，并向客户端一次性注入 −8 秒时钟偏差。收到同一条充能状态时，旧公式计算出 **4.818 秒**，新显示为 **4.000 秒**，随后连续递减。这是故障注入结果；本轮普通新启动未复现历史的 7.54 秒。

显示仍受状态复制和传输延迟影响，服务器确认的可用次数始终优先。本地倒计时归零不会自行发放充能。

## 状态与时钟

- `NextChargeReadyServerTime`：服务器保存的本轮截止时间，服务器 TimerManager 仍负责恢复次数。
- `SnapshotServerTime`：状态改变时记录的服务器游戏时间，与截止时间使用同一时钟。
- `RechargeSequence`：每次开始补充一格时递增。只有新的周期可以重新开始完整倒计时。
- `ResetEpoch`：换人和 Pawn 更替的隔离标记，沿用已有预测请求清理机制。
- `ClientRechargeDeadline`：客户端收到状态时，用本地游戏时间加快照剩余时长建立的显示截止时间。同周期更新取较早值，满充能清零。

复制仍使用原有 `COND_OwnerOnly` 充能结构，没有增加逐帧 RPC 或修改引擎全局对时算法。伤害、击杀与助攻缩短充能的权威计算路径保留；本批只改快照发布与客户端显示。客户端计时已到零、服务器尚未确认可用次数时，零格 HUD 显示“等待充能”。

这种方案将显示与 GameState 的时钟估计分开，但不会消除网络传输时间。快照在传输、重发或合并期间可能变旧；客户端最终按新的权威充能数更新。该实现适用于短周期技能 HUD，不能作为精确网络时钟。

## 测试方法与数据

版本为 UE 5.7.4 / Lyra 5.7。一个独立 Dedicated Server 与一个渲染客户端通过同机 Loopback 连接，测试位置预设，技能经 Enhanced Input 发起。普通网络与模拟弱网分别记录，配置延迟不等于实测 RTT。

复用 [跨进程驱动入口](跨进程网络案例.md#在合法宿主中复现)。等待正常 Playing 阶段后选择 Phase、设置起点，客户端发出 `Blink`，随后以 `Console HeroArena.Debug.LogBlinkNetwork <stage>` 采样。

故障测试额外执行客户端命令 `ClockBias -8`：只修改一次 GameState 的时钟差值，后续原生同步继续运行。该命令仅在显式开启的非 Shipping 测试驱动中存在，拒绝绝对值大于 10 秒的参数。它模拟时钟估计偏差，与自然冷启动是不同测试条件。

[修改前普通启动记录](data/blink-countdown-before.json) 与 [修改后分组记录](data/blink-countdown.json) 保存双端阶段、Pawn 身份、次数、计时及原日志指纹。快照日志同时保留旧公式和当前显示结果，4.818 与 4.000 来自同一接收事件。

普通网络的连续三次消费验证了 3→0→1→2→3，同周期显示持续递减，新周期重新计时，Pawn 保持同一实例。最终构建的 [弱网生命周期回归](data/countdown-lifecycle.json) 另外覆盖拒绝恢复、正常消费、充能、Striker/Phase 切换及死亡重生后的 Avatar 绑定；两端待确认请求最终清零，进程退出 0。以上为定向测试，连续消费间重新设置起点以避免碰撞和坠落干扰。

当前测试范围为非打包、同机、单拥有客户端。没有验证公网、休眠恢复、长时间断线或所有时间膨胀场景。
